# ru-geocoder

**Автор:** Миллер Михаил  
**Название проекта:** ru-geocoder

Геокодер для российских адресов на базе данных OpenStreetMap (OSM). В основе поиска лежит виртуальная полнотекстовая таблица **SQLite FTS5** с нечётким доранжированием кандидатов через библиотеку **RapidFuzz**.

---

## Основные возможности

- **Полнотекстовый поиск (FTS5):** быстрый отбор кандидатов с префиксным поиском по токенам (регион, город, улица, дом, организация).
- **Нечёткое ранжирование (RapidFuzz):** сопоставление структуры адреса (улица/дом/корпус) для выбора наиболее релевантных совпадений.
- **Группировка организаций (`orgs`):** если по одному физическому адресу зарегистрировано несколько организаций, они объединяются в один адресный результат со списком всех найденных организаций.
- **Два режима работы:** одиночный геокодинг адреса через CLI и пакетная потоковая обработка файлов.
- **JSON / JSONL вывод:** удобная машиночитаемая структура ответа.

## Использование (CLI)

Запуск осуществляется как модуль: `python3 -m src.cli [параметры]`.

### Доступные флаги

| Флаг | Полное имя | Описание |
|---|---|---|
| `-a` | `--address` | Одиночный адрес в свободной форме для геокодирования |
| `-i` | `--input` | Путь к входному текстовому файлу со списком адресов (пакетный режим) |
| `-o` | `--output` | Путь к выходному файлу для сохранения результатов (формат `.jsonl`) |
| `-n` | `--number` | Максимальное количество вариантов адресов в выдаче (по умолчанию: `1`) |
| `-d` | `--db` | Пользовательский путь к базе данных SQLite (по умолчанию: `data/geocoder.db`) |
| | `--debug` | Режим отладки (вывод полного трейсбэка ошибок) |

---

### 1. Одиночный режим (Single Mode)

Поиск координат и информации для одной адресной строки.

```bash
python3 -m src.cli -a "краснодарский край, березанская, ул. Ленина, д. 28"
```

**Пример вывода (JSON):**
```json
[
  {
    "format_address": "краснодарский край, г. березанская, ул. улица ленина, д. 28",
    "region": "краснодарский край",
    "city": "березанская",
    "street": "улица ленина",
    "house": "28",
    "orgs": [
      "школа №3"
    ],
    "lat": 45.7052916,
    "lon": 39.6002208
  }
]
```

Если по адресу находится несколько организаций, все они будут собраны в списке `"orgs"`.

Для получения нескольких подходящих вариантов адресов используйте флаг `-n`:
```bash
python3 -m src.cli -a "березники, пр. Ленина" -n 3
```

---

### 2. Пакетный режим (Batch Mode)

Обработка текстового файла с адресами (один адрес на строку). Результаты построчно сохраняются в формате JSON Lines (`.jsonl`).

```bash
python3 -m src.cli -i input_addresses.txt -o output_results.jsonl
```

**Пример входного файла (`input_addresses.txt`):**
```text
Москва, Тверская 12
краснодарский край, березанская, ул. Ленина, д. 28
Несуществующий адрес 99999
```

**Пример выходного файла (`output_results.jsonl`):**
```json
{"initial_address": "Москва, Тверская 12", "status": "success", "format_address": "московская область, г. москва, ул. тверская, д. 12", "address_components": {"region": "московская область", "city": "москва", "street": "тверская", "house": "12", "orgs": []}, "lat": 55.7595, "lon": 37.6111}
{"initial_address": "краснодарский край, березанская, ул. Ленина, д. 28", "status": "success", "format_address": "краснодарский край, г. березанская, ул. улица ленина, д. 28", "address_components": {"region": "краснодарский край", "city": "березанская", "street": "улица ленина", "house": "28", "orgs": ["школа №3"]}, "lat": 45.7052916, "lon": 39.6002208}
{"initial_address": "Несуществующий адрес 99999", "status": "not_found"}
```

Возможные статусы строки в пакетном режиме:
- `"success"` — адрес успешно найден;
- `"not_found"` — совпадений в базе данных не найдено;
- `"parse_error"` — строка адреса пуста или не содержит распознаваемых токенов.

---

### 3. Режим отладки (Debug Mode)

Для анализа ошибок и вывода расширенных трейсбэков используйте флаг `--debug`:

```bash
python3 -m src.cli -a "новосибирск" --debug
```

#### Коды возврата CLI (Exit Codes):
- `0` — Успешное выполнение (`Success`);
- `1` — Обработанная ошибка геокодера или адрес не найден (`Handled Error`);
- `2` — Критическая или непредвиденная ошибка (`Critical Error`).

## Веб-интерфейс и API (FastAPI)

Проект включает в себя веб-приложение и REST API на базе **FastAPI** с интерактивной картой на **Leaflet.js** (`static/index.html`), где результаты поиска отображаются под картой.

### Запуск веб-сервера

Для запуска сервера разработки через `uvicorn`:

```bash
uvicorn src.web.app:app --reload
```

После запуска перейдите в браузере по адресу: [http://127.0.0.1:8000](http://127.0.0.1:8000).

### API Endpoints

- `GET /` — возвращает HTML-интерфейс с картой и поиском.
- `GET /api/geocode` — REST API для геокодирования адресов.
  - **Query-параметры:**
    - `address` (string) — искомый адрес в свободной форме.
    - `limit` (int, опционально, по умолчанию `1`) — количество возвращаемых вариантов.
  - **Пример запроса:**
    ```bash
    curl "http://127.0.0.1:8000/api/geocode?address=Москва,%20Тверская%207&limit=1"
    ```
  - **Пример ответа (JSON):**
    ```json
    {
      "status": "success",
      "data": [
        {
          "format_address": "московская область, г. москва, ул. тверская, д. 7",
          "region": "московская область",
          "city": "москва",
          "street": "тверская",
          "house": "7",
          "orgs": [],
          "lat": 55.7595,
          "lon": 37.6111,
          "similarity_score": 100.0
        }
      ]
    }
    ```

## Архитектура проекта

```text
ru-geocoder/
├── data/
│   ├── geocoder.db           # Основная база данных SQLite с FTS5 таблицей адресов
│   └── import_data.db        # Скрипт для инициализации БД из .geojson и .pbf файлов
├── src/
│   ├── core/
│   │   ├── db_client.py      # DBClient: взаимодействие с SQLite FTS5 (контекстный менеджер, запросы)
│   │   ├── parser.py         # AddressParser: очистка стоп-слов, токенизация и выделение структуры
│   │   └── engine.py         # GeocoderEngine: координация поиска, ранжирование и группировка
│   ├── web/
│   │   └── app.py            # FastAPI приложение и REST API эндпоинты
│   ├── cli.py                # Консольный интерфейс argparse
│   └── exceptions.py         # Пользовательские исключения проекта
├── static/
│   └── index.html            # Веб-интерфейс с поиском и интерактивной картой (Leaflet.js)
├── tests/                    # Набор модульных и интеграционных тестов (pytest)
│   ├── test_cli.py
│   ├── test_db_client.py
│   ├── test_engine.py
│   ├── test_parser.py
│   └── test_data/
│       ├── geocoder_test.db  # Тестовая база данных SQLite
│       └── init_test_db.py   # Скрипт инициализации тестовой БД
├── requirements.txt          # Зависимости проекта
└── README.md
```

- **`AddressParser`**: очищает входную строку от пунктуации и мусорных/стоп-слов (`г.`, `ул.`, `д.`), извлекает токены для FTS5 и регулярными выражениями выделяет ключевые части адреса (улица, дом, корпус) для ранжирования.
- **`DBClient`**: выполняет полнотекстовый поиск в FTS5-таблице `addresses` по префиксным токенам (`token*`).
- **`GeocoderEngine`**: связывает парсер и БД, отправляет расширенную выборку кандидатов в RapidFuzz, ранжирует их по схожести и группирует несколько организаций по одному физическому адресу в массив `orgs`.
- **`FastAPI App (`src/web/app.py`)`**: предоставляет REST API (`/api/geocode`) и раздает статический веб-интерфейс.
- **`Web UI (`static/index.html`)`**: пользовательский интерфейс с поисковой строкой, отображением результатов под картой и интерактивными маркерами Leaflet.js.
- **`CLI`**: обрабатывает аргументы командной строки, форматирует вывод и управляет потоками в одиночном и пакетном режимах.
